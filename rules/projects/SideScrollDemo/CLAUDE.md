# SideScrollDemo 仓库规则（Cursor / Claude 共用）

> 与用户全局规则对齐；本仓库以本文件 + `TF_Cjy/` 文档约定为准。

1. 全程中文；文件引用格式 `[文件名](相对路径)`
2. 【业务代码】定义：业务逻辑、UI脚本、数据配置、实体结构；纯注释、排版、文案微调、工具脚本改动豁免，无需计划
3. 修改/新增业务代码前：按计划模板写方案，存 `TF_Cjy/Plans/yyyyMMdd_HHmmss_简述.md`；本轮只发方案，**不写代码**，等待确认  
   （模板源：`C:\Users\chen\.cursor\hooks\plan-template.md`）
4. 确认触发：单独消息「确认/ok/可以/yes/开始/行」，获批后可批量改多文件，无需重复问询
5. 规则边界：
   - 新需求 / 超出原计划范围改动 → 重写方案，旧确认失效
   - 计划内细小调整可直接执行
6. **收尾更新技术文档**（与计划案同一闭环）：
   - 更新 [`TF_Cjy/Docs/项目技术文档.md`](TF_Cjy/Docs/项目技术文档.md)
   - 只改触及章节，保持结论态；文末「变更日志」只追加
   - 豁免同第 2 条；`Learn/` 不强制同步
7. 编码规范：
   - 类私有成员变量统一使用 `m_` 前缀命名
   - 单文件单一职责，`#region` 分块；公开字段/接口必须注释
8. 运行安全 / GC：空引用判断；Update 内禁止加载/查找/字符串拼接/new 集合；循环内禁止临时分配
9. 临时文件统一放入 `TF_Cjy/{Plans|Temp|Intermediate|Other|Docs}/`
10. 修改完毕固定询问：效果是否符合预期，是否撤销或继续调整

## 文档分工

| 路径 | 用途 |
|------|------|
| `TF_Cjy/Plans/` | 改前：本次意图与范围 |
| `TF_Cjy/Docs/项目技术文档.md` | 改后：当前架构真相 + 变更日志 |
| `TF_Cjy/Learn/` | 可选教学案，不要求每次更新 |
